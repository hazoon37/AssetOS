# Smart Import Specification

이 문서는 Smart Import, Excel 가져오기와 Asset Resolver 동작의 단일 규범
명세다. 다른 문서의 요약과 내용이 다르면 이 문서를 우선한다.

## Purpose

Smart Import는 사용자가 아는 최소 정보만 입력해도 AssetOS 자산 레코드를
만들 수 있게 한다. 자동조회는 편의를 제공하지만 사용자 확인과 데이터
정확성보다 우선하지 않는다.

제품 원칙은 **input minimum, analysis maximum**이다. 사용자는 자신이 아는
정보만 제공하고, 시스템은 가능한 필드를 해결한 뒤 해결하지 못한 항목만
명확하게 요청한다.

## Input contract

최소 필수 입력은 다음 두 항목이다.

- `자산명`
- `수량`

다음 항목은 선택 입력이며 유효한 사용자 입력이 자동조회보다 우선한다.

- 자산종류, 티커, 평균단가, 현재가, 통화
- 거래소, 국가, 자산군, 섹터, 산업과 기타 메타데이터

기존 전체 스키마 Excel 파일과 `Assets` 시트는 계속 허용한다. 일반 Excel은
첫 시트의 알려진 열 이름을 표준 열로 자동 매핑하며 알 수 없는 추가 열은
가져오기 결과를 변경하지 않아야 한다.

표준 템플릿의 `Ticker` 열은 선택 사항이다. 비어 있으면 자산명으로 해결하고,
입력되어 있으면 해당 티커를 먼저 검증한 뒤 표준 대문자 티커를 사용한다. 입력
Ticker가 확인되지 않으면 중단하지 않고 Asset Name으로 같은 resolver 전체
파이프라인을 다시 실행한다.

AssetOS 표준 파일의 열 이름은 앞뒤 공백을 제외하고 정확히 유지한다. 일반
Excel은 공백·구분문자·대소문자를 정규화한 뒤 명시된 alias 사전으로만 매핑한다.
행 순서는 의미를 가지지 않지만 미리보기와 오류 행 번호는 원본 순서를 유지한다.

## Import mode and compatibility

- 기본 적용 모드는 Excel의 유효 행으로 사용자가 선택한 투자계정의 자산을
  **전체 교체**하는 것이다.
- 전체 교체 사실과 반영될 행 수를 Apply Changes 전에 명확히 표시한다.
- 병합, upsert 또는 중복 제거를 전체 교체처럼 보이게 암묵적으로 수행하지 않는다.
- `ID`, 생성일과 수정일은 내보내기 호환 정보다. 가져오기에서 DB 식별자를 강제로 재사용하지 않는다.
- 기존 선택 열과 메타데이터를 포함한 파일은 같은 검증·미리보기·백업 흐름을 사용한다.
- 빈 유효 행 목록은 현재 DB 삭제 요청으로 해석하지 않고 오류로 처리한다.

## Resolution pipeline

1. AssetOS 형식, 일반 Excel 또는 등록된 broker adapter 형식을 감지하고 대상 시트를 읽는다.
2. 필수 열과 각 행의 자산명·수량을 검증한다.
3. 사용자 입력을 정규화하되 원본을 덮어쓰지 않는다.
4. 공유 Asset Master, 별칭 사전, 정확한 티커, 한국어 회사명, 영어 회사명,
   부분 일치, fuzzy matching 순으로 로컬 검색한다.
5. 로컬 결과가 없을 때만 Yahoo Finance, KRX 또는 등록된 시장 제공자를 조회한다.
6. 모든 로컬·시장 제공자가 실패한 경우에만 선택적 AI resolver를 마지막으로 호출한다.
7. 자동 임계값 이상의 단일 결과면 즉시 메타데이터와 티커를 채운다.
8. 임계값 이상의 관련 후보가 여러 개일 때만 `ambiguous`로 반환하고 사용자가 고르게 한다.
9. 선택된 시장 자산의 현재가를 가격 제공자에서 조회한다.
10. 사용자 입력과 자동조회 결과를 병합한다.
11. 최종 미리보기와 검증 상태를 표시한다.
12. 확인과 `Apply Changes` 이후에만 저장한다.

각 단계는 이전 단계의 결과를 입력으로 사용한다. 파일 내용 또는 사용자 편집이
바뀌면 그 이후 단계만 다시 실행하되, 오래된 후보나 가격을 새 파일에 재사용하지 않는다.

Ticker Resolver와 시장가격 조회는 주식·ETF·암호자산에만 실행한다. 예금, 현금,
CMA, MMF, 적금과 입출금계좌 등 검색이 불필요한 자산은 경고 없이 `⚪ Skip`
상태로 통과시킨다.

자산명에 `계좌`, `예수금`, `위탁`, `종합매매`, `CMA`, `입출금`, `외화예수금`,
`외화계좌`, `RP`, `MMF`, `증거금`이 포함되면 자산종류보다 먼저 `Account`로
분류한다. 이 규칙은 resolver보다 우선하며 ticker 후보·직접 입력 UI를 표시하지 않는다.

## Resolver result states

- `exact`: 정확한 이름·별칭·티커 일치
- `fuzzy`: 기준 점수 이상의 단일 유사 일치
- `ambiguous`: 둘 이상의 유효 후보. 자동 선택 금지
- `unknown`: 후보 없음. 수동 입력 흐름 제공

각 후보는 가능한 경우 ticker, exchange, currency, country, asset_type,
sector, display_name을 제공한다. 제공자를 추가해도 호출자는 같은 resolver
계약을 사용한다.

## Resolver matching rules

- 이름 비교 전 Unicode, 대소문자, 앞뒤 공백과 연속 공백을 정규화한다.
- 정확한 티커와 명시적 별칭은 fuzzy 결과보다 우선한다.
- `resources/alias_dictionary.json`은 100개 이상의 글로벌 종목 티커를 지원하며
  프로세스에서 한 번만 읽어 같은 파일 rerun의 중복 조회를 피한다.
- fuzzy threshold와 동점 허용 범위는 서비스에서 한 곳에 정의하고 테스트한다.
- 자동 확정 임계값과 후보 표시 임계값은 분리한다. 자동 확정 기준에 미달해도
  후보 기준을 통과한 provider 결과는 삭제하지 않고 dropdown에 모두 전달한다.
- 다른 거래소의 동일 티커, 보통주·우선주, 주식·ETF는 서로 다른 후보로 유지한다.
- 제공자 결과는 표준 ticker와 exchange 조합으로 중복 제거한다.
- 후보 순위만으로 첫 항목을 자동 선택하지 않는다.
- resolver는 결과 상태와 함께 match type, provider와 가능한 경우 confidence를 제공할 수 있어야 한다.
- 자동 확정 임계값에 미달한 행은 신뢰 가능한 후보 dropdown을 먼저 표시하고,
  같은 Ticker 셀 안에 회사명·티커 검색과 직접 입력을 함께 제공한다. 한 방법을
  표시하기 위해 다른 방법이나 기존 후보를 숨기지 않는다.

## Provider precedence

v1.0 로컬 일치 순서는 Asset Master 한국어 회사명 → Asset Master 영문 회사명 →
내부·학습 별칭 → 정확한 티커 → 부분·fuzzy 검색이다. 로컬 검색이 모두 실패한
경우에만 시장 제공자를 호출한다. AI resolver는 설정된 경우에도 모든 앞 단계가
실패한 뒤에만 실행한다.

- 내부 별칭: 자주 쓰는 한국어·영어 이름과 티커의 결정적 해석
- KRX: 국내 상장주식과 ETF의 종목명, 코드와 시장
- CoinGecko: 암호자산 심볼과 표준 ID
- Yahoo Finance: 해외주식·ETF 검색과 시장 메타데이터

공유 Asset Master의 논리 스키마는 `ticker`, `asset_type`, `company_name`,
`company_name_ko`, `aliases`, `exchange`, `currency`, `status`다. 분석용 확장
메타데이터는 같은 레코드에 보존한다. 정적 CSV와 학습 overlay는
`asset_master_service`에서 하나의 읽기 모델로 병합되며 호출자가 별도 매핑을
유지하지 않는다.

로컬 Asset Master는 삼성전자, 삼성전기, NAVER, 셀트리온, 한화오션,
현대글로비스, 카카오뱅크, HMM, 우진엔텍을 포함한 주요 KRX 종목과 ACE·TIGER·KODEX 대표 ETF의
한국어·영문명·6자리 코드를 보유한다. 이 항목들은 외부 조회나 후보 선택 없이
정확 일치로 해결한다.

한 제공자가 확정 결과를 반환하면 불필요한 다음 조회를 생략할 수 있다. 다만
서로 충돌하는 확정 결과가 있으면 출처 우선순위 또는 사용자 선택으로 해결하며
조용히 덮어쓰지 않는다.

## Merge and manual override rules

- 비어 있지 않고 유효한 사용자 입력이 최우선이다.
- 자동조회는 비어 있는 필드만 채운다.
- 자동조회 값은 편집 가능한 미리보기에서 원본 입력과 함께 검토한다.
- 사용자는 자산명, 티커, 자산종류, 수량, 평균단가, 현재가, 통화, 거래소와 국가를 수정할 수 있다.
- 상태 열은 Resolver 결과를 설명하는 읽기 전용 값이며 저장 필드를 대신하지 않는다.
- 편집값은 Apply Changes 전에 필수값, 숫자 범위와 행 수를 다시 검증한다.
- 파일이 변경되면 이전 후보와 편집 상태를 폐기한다.
- Ticker dropdown과 수동 입력은 파일별 `session_state`에만 누적한다. 선택 시
  DB를 변경하거나 dialog를 닫는 전체 화면 rerun을 호출하지 않으며 여러 행을
  연속으로 수정한 뒤 Apply Changes에서 한 번만 검증·저장한다.

## Price and profit rules

- 현재가 조회 성공 시 `수량 × 현재가`로 현재 평가금액을 표시한다.
- 현재가 조회 실패는 resolver 성공 상태를 `Fail`로 낮추지 않는다. 해당 행은
  `Auto`를 유지하고 `Price unavailable` 경고를 별도로 표시한다.
- 평균단가가 있으면 투자원금, 평가손익과 수익률을 계산한다.
- 평균단가가 없으면 현재 평가금액만 계산하고 평가손익과 수익률은 `계산 불가`로 유지한다.
- 알 수 없는 평균단가를 `0` 또는 현재가로 대체해 실제 원가처럼 저장하지 않는다.
- 가격에는 provider, 조회 시각, 거래통화와 stale 여부를 함께 유지한다.
- 캐시 만료 기준을 넘긴 가격은 최신값처럼 표현하지 않는다.
- 현금·예금은 사용자가 정의한 단가 또는 잔액 규칙을 사용하고 시장가격 조회를 강제하지 않는다.
- 부동산·수집품 등 비시장 자산은 수동 현재가를 허용하고 자동조회 실패를 오류로 취급하지 않는다.

## Ambiguity UX

- 기본 후보를 자동 선택하지 않는다.
- ambiguous와 unknown 행은 `Needs Review` 상태와 `UNRESOLVED` 태그로 보존한다.
- 후보 선택기는 첫 후보를 기본 선택하지 않는다. 사용자가 명시적으로 선택한
  경우에만 해당 메타데이터와 현재가를 다시 보강한다.
- Smart Import에는 Row, Type, Asset, Ticker, Status 순서의 단일 작업 표만
  표시한다. 상태는 `🟢 Auto`, `🟡 Select`, `⚪ Skip`, `🔴 Fail`을 사용한다.
  Ticker dropdown은 모든 신뢰 가능한 후보 뒤에 `✏ 직접 입력...`을 마지막
  항목으로 표시한다. 이 항목을 선택한 경우에만 같은 셀이 편집 모드가 되며,
  후보 목록을 직접 입력으로 대체하지 않는다.
- 검증·조회 오류와 경고는 미리보기에 표시된 동일한 Row Number를 사용한다.
- 결과 화면은 Total, Auto, Select, Skip, Fail 요약과 상태 필터를 제공한다.
  `Import_Error.xlsx`는 업로드 원본 열을 유지한 채 Status와 Suggested Action만
  덧붙인다.
- 저장 가능한 원본 자산명·수량은 유지하고 조회 실패가 전체 파일 검토를 중단시키지 않는다.

## User flow and state lifecycle

- 대량 변경은 계정 선택 → 파일 선택 → 검증 → 자동 해결 → 편집 가능한 미리보기 → 재검증 → 확인 → `Apply Changes` 순서다.
- 업로드만으로 DB를 변경하지 않는다.
- 파일이 바뀌면 이전 미리보기, 후보 선택, 편집값, 가격 결과와 확인 상태를 초기화한다.
- 검증 오류가 발생해도 동일 파일의 수정 가능한 입력은 가능한 범위에서 보존한다.
- 닫기와 취소는 DB를 변경하지 않으며, 적용 성공 후 임시 상태를 정리한다.
- 오류는 행·필드, 이유와 해결 방법을 표시하고, 경고는 적용 가능 여부를 명확히 구분한다.
- 성공 시 반영된 자산 수와 백업 여부를 알린다.

## Validation

적용을 막는 오류:

- `Assets` 시트 또는 필수 열 누락
- 비어 있는 자산명 또는 수량
- 숫자가 아닌 수량·가격
- 음수 수량 또는 가격
- 해결되지 않은 자산명 또는 수량

적용을 막지 않는 경고:

- 수량이 0인 행
- 평균단가 누락
- 선택 메타데이터 누락
- 최신 가격 조회 실패 후 허용된 수동·비시장 자산

## Duplicate and row rules

- 완전히 빈 행은 무시한다.
- 동일 파일에서 표준 ticker와 exchange가 같은 행이 여러 개면 자동 합산하지 않고 경고한다.
- 이름은 같지만 서로 다른 ticker 또는 exchange인 행은 별도 자산으로 유지한다.
- 수량 0은 경고이며 사용자가 의도적으로 유지할 수 있다.
- 동일 자산의 여러 매입 lot을 하나로 합치는 규칙은 Smart Import 범위 밖이다.
- 수식 셀은 Excel 계산 결과가 안전하게 읽히는 경우에만 값으로 처리하며 수식을 실행하지 않는다.

## File safety and limits

- 허용 형식은 `.xlsx`이며 매크로 포함 파일을 실행하지 않는다.
- 압축 해제 크기, 행 수와 파일 크기에 합리적인 상한을 두고 초과 시 해결 방법을 안내한다.
- 업로드 파일명은 표시용이며 파일 경로나 저장 대상을 결정하는 데 사용하지 않는다.
- 오류 메시지와 로그에 전체 자산 원본, 로컬 경로 또는 비밀정보를 남기지 않는다.
- 미리보기는 필요한 행과 열만 메모리에 유지하고 대용량 파일 전체를 복제하지 않는다.
- API 키, 계정정보와 비밀값을 가져오기 파일, 로그 또는 외부 resolver 요청에 포함하지 않는다.
- 외부 제공자에는 해결에 필요한 이름·티커·통화만 전달한다.

## Provider and performance rules

- resolver 호출자는 Yahoo Finance, KRX, CoinGecko를 직접 호출하지 않는다.
- 제공자는 공통 결과 계약을 구현하고 실패 시 다음 제공자로 제어를 넘긴다.
- 조회에는 제한시간, 캐시와 결과 수 제한을 둔다.
- 동일 파일의 Streamlit rerun에서 불필요한 재조회를 하지 않는다.
- 한 제공자의 장애가 파일 검증, 수동 수정 또는 기존 형식 가져오기를 막지 않는다.
- 동시 조회 수와 재시도 횟수를 제한하고 rate limit 응답에는 backoff를 적용한다.
- 실패 결과는 성공 결과보다 짧게 캐시해 복구 후 재시도가 가능해야 한다.
- Portfolio, Smart Import, Current Price와 AI Advisor는 같은 Asset Resolver
  계약을 사용한다. Portfolio와 AI의 렌더링 경로는 불필요한 네트워크 조회 없이
  로컬 Asset Master와 학습 별칭까지만 사용한다.

## Learned Asset Master

- 사용자가 후보를 선택하거나 유효한 티커를 직접 입력하면 원본 Asset Name과
  표준 ticker 연결을 `data/learned_asset_master.json`에 원자적으로 저장한다.
- 직접 입력이 대문자 ticker 형식이면 회사명 검색보다 먼저 시장 provider에서
  exact ticker로 검증한다. 성공하면 ticker, 회사명, 거래소와 표준 메타데이터를
  Asset Master에 저장하고, 실패한 경우에만 회사명·alias 검색을 계속한다.
- 신뢰 임계값을 통과한 온라인 확정 결과도 표준 메타데이터와 검색어를 같은
  overlay에 저장해 다음 조회부터 오프라인으로 해결한다.
- 번들 `resources/alias_dictionary.json`은 수정하지 않는다.
- 저장 직후 alias와 검색 캐시를 무효화해 다음 import부터 정확 일치로 처리한다.
- 티커 검증에 실패하거나 파일시스템이 쓰기 불가능하면 학습하지 않되 현재
  session의 선택과 import 작업은 계속 진행한다.

## Fallback behavior

- `unknown`: 사용자에게 자산종류, 통화와 현재가를 직접 입력할 수 있게 한다.
- `ambiguous`: 자동 선택하지 않고 `Needs Review`로 저장해 후속 검토가 가능하게 한다.
- 메타데이터 일부 누락: 필수 저장 필드만 해결되면 경고와 함께 진행할 수 있다.
- 가격 제공자 실패: 기존 사용자가 입력한 현재가를 유지하고, 없으면 자산종류별 정책을 적용한다.
- 네트워크 없음: 로컬 검증, 내부 별칭, 미리보기와 수동 입력은 계속 사용할 수 있어야 한다.
- 일부 행 실패: 성공한 행만 조용히 적용하지 않고 전체 파일 상태를 사용자에게 보여준다.

## Apply semantics

- 업로드와 조회는 DB를 변경하지 않는다.
- Apply Changes는 Fail과 Select 행 수를 다시 계산한다. 하나라도 남으면 모든
  문제 개수를 안내하고 저장하지 않는다.
- 적용 직전에 현재 DB를 백업한다.
- 모든 행은 선택한 계정 안에서 하나의 원자적 트랜잭션으로 반영한다.
- 실패하면 전체 변경을 롤백한다.
- 성공 후 관련 분석 캐시를 초기화하고 반영 수와 백업 위치를 알린다.

## Quick Analysis semantics

- Quick Analysis는 동일한 파일 감지, 열 매핑, 검증, Resolver, 가격 조회와 편집 미리보기를 사용한다.
- `Analyze Only` 실행은 Repository의 save, replace, backup 또는 snapshot API를 호출하지 않는다.
- 업로드 원본, 보강 행, 편집 행, 분석 결과와 export bytes는 현재 `session_state`에만 둔다.
- 파일이 변경되면 이전 임시 행, 분석과 export를 즉시 폐기한다.
- PDF·PNG·JSON 다운로드가 완료되어도 영구 자산 DB에는 반영하지 않는다.
- `Save into AssetOS`는 분석과 export 이후 대상 계정, 전체 교체와 백업을 명시적으로 확인한 경우에만 기존 `import_asset_rows`를 호출한다.

## Audit and provenance

각 반영 행은 가능한 범위에서 다음 정보를 추적할 수 있어야 한다.

- 사용자가 입력한 원본값
- 최종 적용값
- 선택한 resolver 후보와 provider
- 가격 provider와 조회 시각
- 수동 override 여부
- 경고와 fallback 사유

이 정보는 사용자의 자산 데이터와 같은 개인정보 보호 원칙을 따른다.
