# AssetOS UX Rules

## Information hierarchy

- 대시보드는 핵심 KPI, 자산 배분, 상·하위 성과, 요약 순으로 보여준다.
- 포트폴리오는 기존 분석 구조를 유지하고 상세 분석을 담당한다.
- 종목분석은 개별 자산 탐색에 집중한다.
- 한 화면에서 가장 중요한 기본 행동은 하나의 primary 버튼으로 표현한다.

## Navigation and asset management

- 왼쪽 메뉴는 대시보드, 포트폴리오, 종목분석의 세 페이지로 제한한다.
- `➕ 자산관리`는 대시보드 상단의 빠른 진입점이다.
- 짧고 맥락을 유지해야 하는 작업은 dialog를 우선한다.
- dialog가 중첩되거나 작은 화면에서 사용하기 어려우면 expander 또는 페이지 내 컨테이너를 사용한다.
- 자산관리의 모든 진입점은 같은 서비스와 저장 경로를 재사용한다.

## Responsive layout

- Desktop (`> 1024px`): 핵심 KPI 4열, 비교 표와 차트는 가능한 경우 2열
- Tablet (`641px–1024px`): 핵심 KPI 2열
- Mobile (`≤ 640px`): 핵심 KPI와 작업 영역 1열
- 표는 핵심 열을 먼저 배치하고 가로 스크롤에서도 자산명과 상태를 식별할 수 있어야 한다.
- 버튼은 터치하기 충분한 높이를 유지하고 중요한 작업은 전체 너비를 사용할 수 있다.

## Readability and visual consistency

- KPI 카드의 높이, 안쪽 여백, 제목과 값의 위치를 일관되게 유지한다.
- 색상만으로 손익·오류·상태를 전달하지 않고 텍스트 또는 아이콘을 함께 사용한다.
- 금액에는 통화 또는 원화 환산 여부를 표시한다.
- 날짜와 가격에는 기준 시점 또는 갱신 상태를 표시한다.
- 빈 상태는 다음 행동을 안내하고, 계산 불가 상태는 이유를 설명한다.

## Feedback and errors

- 네트워크 작업에는 진행 상태를 표시한다.
- 오류 메시지는 문제가 발생한 행·필드, 이유, 해결 방법을 포함한다.
- 경고와 오류를 구분한다. 오류는 적용을 막고, 경고는 사용자가 검토 후 진행할 수 있다.
- 성공 메시지는 변경된 자산 수와 백업 여부를 알려준다.
- 외부 서비스의 원문 예외나 비밀정보를 사용자에게 노출하지 않는다.

## Destructive and bulk actions

- 적용 직전에 백업하고 전체 변경은 원자적으로 처리한다.
- Smart Import의 업로드, 미리보기, 확인과 적용 흐름은 `SMART_IMPORT_SPEC.md`를 따른다.

## Accessibility

- 제목 구조를 순서대로 사용하고 입력에는 명확한 레이블을 제공한다.
- 키보드만으로 주요 작업과 후보 선택이 가능해야 한다.
- 본문과 컨트롤은 충분한 대비를 유지한다.
- 도움말은 필수 정보를 대신하지 않으며, 핵심 안내는 화면에 직접 표시한다.

## Dialog and state lifecycle

- dialog를 열어도 배경 페이지의 필터와 스크롤 맥락을 가능한 한 유지한다.
- 닫기, 취소와 적용의 의미를 구분하고 destructive action은 취소를 항상 제공한다.
- dialog 안에서 다른 dialog를 중첩하지 않는다. 후보 선택은 현재 dialog 안의 별도 단계나 컨테이너로 표시한다.
- 적용 성공 후 dialog 상태를 정리하고 데이터가 갱신된 화면을 보여준다.
- Smart Import의 파일 변경과 임시 상태 규칙은 `SMART_IMPORT_SPEC.md`를 따른다.

## Tables and charts

- 표의 기본 정렬 기준을 제목이나 설명에서 알 수 있어야 한다.
- 금액, 비율과 수량은 데이터 의미에 맞는 자릿수를 일관되게 사용한다.
- TOP 목록은 동률 처리와 정렬 방향이 결정적이어야 한다.
- 차트 범례와 색상은 같은 자산군에 대해 화면 간 일관되어야 한다.
- 차트만으로 제공되는 핵심 정보는 표 또는 텍스트 요약으로도 확인할 수 있어야 한다.
- 모바일에서 보조 열은 뒤로 배치하되 원본 데이터를 삭제하거나 의미를 축약하지 않는다.

## Language and terminology

- 기본 사용자 문구는 한국어로 쓰고 티커, API, Asset Resolver 같은 고유 기술 용어만 필요한 범위에서 병기한다.
- 동일 개념에는 동일 용어를 사용한다. 예: `현재가`, `평균단가`, `평가금액`, `평가손익`.
- 버튼은 행동을 표현한다. 기능별 정확한 레이블은 해당 기능 명세를 따른다.
- 내부 필드명, 스택 트레이스와 제공자 응답 코드를 사용자 문구로 그대로 노출하지 않는다.

## Loading and perceived performance

- 첫 화면 렌더링에 필요하지 않은 Excel 생성, PDF 생성과 외부 조회는 사용자 행동 이후 수행한다.
- 여러 행을 조회할 때 전체 진행률과 현재 처리 대상을 보여준다.
- 캐시된 결과와 새로 조회한 결과를 혼동하지 않도록 기준 시점 또는 갱신 상태를 표시한다.
- 장시간 작업은 취소 또는 안전한 재시도 경로를 제공하도록 설계한다.
